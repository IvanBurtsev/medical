# ТЗ модуля 2 — «Радар конкуренции»

**Статус:** на юридической оценке. Реализация до заключения не запускается.

---

## 1. Объект и цель

**Объект:** дистрибьюторы и интеграторы медицинского/стоматологического
оборудования — конкуренты MedAX Group.

**Цель:** собрать публичную информацию о товарных предложениях конкурентов
(цена, акция, бренд, регион) и сопоставить с каталогом MedAX для оценки
ценового позиционирования.

**НЕ является целью:** получение коммерческой тайны, персональных данных,
закрытой информации; воздействие на работоспособность сайтов.

---

## 2. Предмет сбора

| Поле | Источник | Тип |
|---|---|---|
| Наименование товара | Публичная карточка каталога | Публичные данные |
| Цена | Публичный прайс/карточка | Публичные данные |
| Бренд/производитель | Публичная карточка | Публичные данные |
| Акция/промо | Публичный раздел акций | Публичные данные |
| Регион | Публичная страница | Публичные данные |
| URL | Адрес страницы | Служебное |

## 3. Явные ограничения (must / must not)

**Допустимо:**
- Собирать только страницы, открытые без авторизации.
- Соблюдать `robots.txt` и `Crawl-delay`.
- Ограничивать частоту запросов (token bucket, per-host).
- Кэшировать `robots.txt`.
- Идентифицировать бота в User-Agent.

**Недопустимо:**
- Обход авторизации, капчи, paywall.
- Подмена личности, использование чужих учётных данных.
- Запросы, создающие чрезмерную нагрузку (по сути DDoS).
- Сбор персональных данных сотрудников, отзывов с именами и т.п.
- Извлечение и использование сведений, составляющих коммерческую тайну.

## 4. Архитектурные требования

```
Список доменов (allowlist)
        │
        ▼
RobotsCache ──► отказ при Disallow
        │
        ▼
HostRateLimiter ──► token bucket на домен
        │
        ▼
HttpClient (retry/backoff, UA, Retry-After)
        │
        ▼
Парсер страницы ──► CompetitorOffer
        │
        ▼
Хранилище (РФ) ──► отчёт о позиционировании
```

Все элементы, кроме парсера конкретного сайта, **уже реализованы** в
`medax_radar/net/` и покрыты тестами.

## 5. Требования к данным

- Хранить только публичные атрибуты из §2.
- Не хранить HTML-страницы целиком дольше необходимого.
- Хранить дату сбора и URL-источник (аудит происхождения).
- Возможность удаления данных по требованию (data erasure).

## 6. Режим запуска

- Только после письменного юридического заключения.
- Ведение журнала доступа (какие домены, когда, сколько запросов).
- Ручное подтверждение allowlist доменов.
- Возможность мгновенного приостановления сбора.

## 7. Критерии приёмки модуля 2

1. Покрытие ≥ 70% ключевых SKU-конкурентов.
2. 0 обращений правообладателей о нарушениях.
3. 0 запросов в обход robots.txt.
4. Наличие отчёта «наш SKU ↔ конкурент» с разницей цен.
