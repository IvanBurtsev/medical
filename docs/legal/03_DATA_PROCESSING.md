# Обработка данных и персональные данные

## 1. Принципы

| Принцип | Реализация |
|---|---|
| Минимизация | собираются только поля, необходимые для задачи |
| Ограничение цели | данные используются только для B2B-аналитики |
| Ограничение хранения | сырые страницы не хранятся; только атрибуты |
| Точность | данные привязаны к URL-источнику и дате |
| Безопасность | локальное хранение в РФ, ролевой доступ |
| Прозрачность | аудит происхождения (source, source_url, captured_at) |

## 2. Персональные данные

- ПДн пациентов **не собираются**.
- ПДн сотрудников клиник **намеренно не извлекаются**.
- Если в открытой выдаче встречаются ПДн, они **удаляются/обезличиваются**
  до сохранения (принцип tokenize-before-storage).
- Отзывы и иные тексты с именами не собираются.

## 3. Правовые основания (по 152-ФЗ)

- Обработка бизнес-контактов организации — в рамках делового общения.
- Обработка общедоступных данных — с учётом целей и минимизации.
- Согласие субъекта не требуется там, где ПДн не обрабатываются.

Точная квалификация — предмет юридического заключения (см. `00_LEGAL_BRIEF.md`).

## 4. Локализация

- Прод-хранилище (PostgreSQL/SQLite) — на территории РФ.
- LLM для ПДн не применяются; для открытых данных допускаются API с
  отключённым хранением (data retention off), если это согласовано юристом.

## 5. Сроки и удаление

| Данные | Срок |
|---|---|
| Сырые страницы | не хранятся (только в памяти) |
| Атрибуты предложений | до 24 месяцев (для динамики цен) |
| Лиды | по политике CRM |
| Логи доступа | 12 месяцев |

Реализуется возможность удаления по требованию (data erasure) на уровне
репозитория.

## 6. Ответственные

- Владелец продукта — общий контроль.
- Ответственный за эксплуатацию — выполнение политики.
- Юрист — оценка и обновление политики (ежеквартально).
