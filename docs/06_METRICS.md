# Метрики успеха MedAX Radar

## 1. Продуктовые метрики (пилот)

| Метрика | Целевое значение | Как измерять |
|---|---:|---|
| Лидов в месяц | ≥ 50 | `db.leads()` |
| Доля «горячих» (HOT) | ≥ 15% | `stats.hot / stats.leads` |
| Точность матчинга категорий | ≥ 80% | выборочная проверка вручную |
| Полезность лидов (подтверждает продажи) | ≥ 30% | обратная связь CRM |
| Полнота контактов | ≥ 70% | доля с телефоном/почтой |
| PII пациентов | 0 | аудит данных |

## 2. Технические метрики

| Метрика | Цель |
|---|---:|
| Время полного прогона пайплайна | < 60 сек (пилот) |
| Доля успешных прогонов без ошибок | ≥ 99% |
| Покрытие источников | 3 открытых + (опц.) конкуренты |
| Uptime дашборда | ≥ 99% |

## 3. Бизнес-метрики (после пилота)

| Метрика | Смысл |
|---|---|
| Cost per lead | Стоимость получения лида |
| Lead → opportunity | Конверсия в возможность |
| Lead → сделка | Конверсия в продажу |
| Влияние на выручку | Атрибуция сделок к радару |

## 4. Антиметрики (на что не закладываться)

- «+46% multi-hop accuracy» из исследовательских работ — не гарантированы
  для нашего домена.
- «1000+ параллельных crawl» — не цель без реальной потребности.
- «Self-healing 90%» — метрика зрелых систем, не пилота.

## 5. Правило калибровки

Веса скоринга пересматриваются **ежемесячно** по фактической конверсии:
если лиды из определённого сигнала не конвертируются — вес снижается.
Все веса — в `config/sources.json`, изменения не требуют правки кода.
