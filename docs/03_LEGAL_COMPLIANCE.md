# Правовой контур и compliance MedAX Radar

> Документ носит инженерно-организационный характер и **не является юридическим
> заключением**. До запуска модуля 2 необходимо заключение практикующего юриста.

> Полный пакет материалов для юридической оценки — в каталоге
> [`docs/legal/`](legal/README.md): бриф, ТЗ модуля 2, политика robots.txt,
> обработка данных, вопросы к юристу и шаблон запроса.

## 1. Открытые данные

Модуль 1 использует государственные открытые данные (реестры Росздравнадзора,
ФНС, закупки). Такие данные:
- опубликованы правообладателем для свободного доступа;
- не содержат персональных данных пациентов;
- собираются в объёмах, не создающих чрезмерной нагрузки.

**Вывод:** юридический риск модуля 1 низкий при соблюдении rate limiting.

## 2. Персональные данные (152-ФЗ)

- Данные пациентов **не собираются**.
- Контактные данные организаций (телефон, e-mail клиники) обрабатываются в
  объёме, необходимом для B2B-коммуникации.
- При появлении любых ПДн применяется принцип **data minimization**:
  не хранить сырые ПДн, обезличивать до сохранения, ограничивать доступ.

### Про отчуждение данных конкурентов
Не путать «публикацию обязательной информации» и «разрешение на любой парсинг».
Единичное судебное решение не является универсальным прецедентом. Поэтому
модуль 2 не строится на предположении «парсить можно всё».

## 3. Ст. 272 УК РФ (неправомерный доступ)

Риск возникает при **преодолении технических ограничений**:
- обход аутентификации;
- игнорирование `robots.txt`;
- обход капчи;
- создание чрезмерной нагрузки (по сути — DDoS).

### Обязательные меры
- Проверка и соблюдение `robots.txt`.
- Адаптивный rate limiting и Circuit Breaker на каждый домен.
- Уважение `Retry-After`, HTTP 429/503.
- Идентификация бота в User-Agent и ссылка на источник.

## 4. EU AI Act

- Продукт предназначен для рынка **РФ**; EU AI Act не является обязательным.
- Функциональность **не относится к high-risk** по Annex III: это не медицинское
  изделие, не HR-скоринг, не кредитный скоринг, не биометрия.
- Практики provenance/lineage полезны инженерно, но не вводятся как юридическое
  требование. Включать только при выходе на рынок ЕС.

## 5. Прочее

| Аспект | Позиция |
|---|---|
| Локализация данных | прод-хранилище — на территории РФ |
| LLM | для ПДн — только локальные/доверенные модели; для открытых данных допустимы API с data retention off |
| Хранение | минимизация, сроки ограничены задачей |
| Доступ | ролевой, минимально необходимый |
| Аудит | логирование прогонов и источников |
