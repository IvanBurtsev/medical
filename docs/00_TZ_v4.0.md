# ТЗ v4.0 — MedAX Radar

**Продукт:** B2B-платформа рыночной разведки и коммерческих сигналов для MedAX Group
**Владелец продукта:** заказчик (owner)
**Версия:** 4.0
**Дата:** 2026-09-21
**Статус:** рабочая версия, готова к пилоту

---

## 1. Резюме

MedAX Radar — внутренний инструмент, который превращает **открытые данные о рынке
медицинских услуг** в **коммерческие сигналы** для отдела продаж и маркетинга MedAX Group.

Продукт решает две задачи:

1. **Радар спроса (модуль 1, приоритет).** Находить новые и расширяющиеся клиники,
   которые скоро будут закупать оборудование, и сопоставлять их с каталогом и услугами MedAX.
2. **Радар конкуренции (модуль 2, после пилота).** Мониторить предложения и цены
   дистрибьюторов-конкурентов, чтобы MedAX понимал своё ценовое позиционирование.

### Ключевой принцип

> **Открытые реестры — сначала, парсинг — потом.**

Модуль 1 строится на государственных открытых данных (низкий юридический риск).
Модуль 2 (парсинг сайтов конкурентов) включается только после юридического заключения.

### Что осознанно НЕ входит в версию 4.0

- Multi-agent оркестрация (MCP + A2A), GraphRAG, Event Backbone (Redpanda).
- Confidential Computing (Intel TDX), AI Governance Platform (OneTrust и т.п.).
- EU AI Act как обязательное требование (продукт для рынка РФ; см. §6).
- Парсинг сайтов клиник как конкурентов (в v4.0 клиники — покупатели).

Эти технологии остаются в разделе «После подтверждения ценности» и вводятся
только при доказанном спросе.

## 2. Объекты и субъекты

| Роль | Кто это | Отношение к продукту |
|---|---|---|
| Продукт | MedAX Radar | Инструмент |
| Заказчик / владелец | MedAX Group | Пользуется, платит за эксплуатацию |
| Целевой пользователь | Отдел продаж, маркетинг MedAX | Получает лиды и отчёты |
| **Клиенты** | Медицинские клиники (стоматология, диагностика, стационары) | **Покупатели оборудования и услуг** |
| **Конкуренты** | Дистрибьюторы мед/стоматологического оборудования, интеграторы «под ключ» | **Объект модуля 2** |
| Источники данных | Росздравнадзор, ФНС/ЕГРЮЛ, zakupki.gov.ru, сайты конкурентов | Сырьё |

**Важно:** в отличие от исходной версии документа, клиники — это **покупатели**,
а не конкуренты. Конкуренты MedAX — другие поставщики и интеграторы.

## 3. Модуль 1 — «Радар спроса» (лид-радар)

### 3.1. Назначение

Формировать список организаций с высоким коммерческим потенциалом и объяснять,
почему они попали в список.

### 3.2. Источники

| Источник | Что даёт | Тип | Юр. риск |
|---|---|---|---|
| Росздравнадзор (реестр лицензий) | Новые лицензии = новые/расширяющиеся клиники | Открытые данные | Низкий |
| ФНС / ЕГРЮЛ | Регистрация новых ЮЛ (ОКВЭД 86.x, 47.73) | Открытые данные | Низкий |
| zakupki.gov.ru (44-ФЗ/223-ФЗ) | Тендеры на медоборудование, НМЦК, заказчики | Открытые данные | Низкий |

### 3.3. Конвейер обработки

```
Источники → Нормализация → Дедупликация → Матчинг с каталогом → Скоринг → Лиды
```

1. **Нормализация.** Очистка названий, регионов, дат; классификация видов
   деятельности по ключевым словам и ОКПД2/ОКВЭД.
2. **Дедупликация.** Слияние записей из разных источников по ИНН, иначе — по
   «название + регион». Обогащение пустых полей.
3. **Матчинг.** Сопоставление видов деятельности клиники и текстов тендеров с
   категориями каталога и услугами MedAX.
4. **Скоринг.** Объяснимая оценка 0–100 по пяти сигналам (см. §5).
5. **Лиды.** Ранжированный список с причинами и рекомендациями.

### 3.4. Пример вывода

```
[HOT 96.9] ООО «Денталь Минводы» — Минеральные Воды, Ставропольский край
  Категории: implantology, xray, dental_units, handpieces
  - Свежая лицензия (3 дн. назад) — высокий шанс закупки
  - Активность госзакупок в регионе: 3 тендера
```

## 4. Модуль 2 — «Радар конкуренции» (после пилота)

### 4.1. Назначение

Мониторинг цен, акций и предложений дистрибьюторов-конкурентов для оценки
ценового позиционирования MedAX.

### 4.2. Требования

- Парсинг только публичных страниц каталога.
- Соблюдение `robots.txt`, адаптивный rate limiting, Circuit Breaker на домен.
- Никакого обхода авторизации, капчи, платных барьеров (иначе — риск ст. 272 УК РФ).
- Запуск **только после письменного юридического заключения**.

### 4.3. Выход

Сопоставление «наш SKU ↔ предложение конкурента» с разницей в цене и акциями.

## 5. Скоринг лидов

| Сигнал | Вес | Логика |
|---|---:|---|
| Свежесть лицензии | 30 | Экспоненциальное затухание, half-life 120 дней |
| Тендерная активность региона | 25 | Число свежих тендеров, half-life 45 дней |
| Приоритет региона | 20 | Близость к базе MedAX (Ставрополь) |
| Совпадение с каталогом | 15 | Кол-во релевантных категорий |
| Полнота данных | 10 | Наличие контактов и реквизитов |

**Уровни:** HOT ≥ 75, WARM ≥ 50, COLD < 50.
Веса настраиваются в `config/sources.json`, без изменения кода.

## 6. Правовой контур (кратко)

- Продукт работает с **открытыми государственными данными** (реестры, закупки).
- Персональные данные пациентов и врачей **не собираются и не хранятся**.
- Модуль 2 (парсинг конкурентов) — после юрзаключения.
- **EU AI Act** не является обязательным для рынка РФ. Продукт не относится к
  high-risk по Annex III (это не медицинское изделие и не HR/кредитный скоринг).
  Требование data provenance полезно как инженерная практика, но не как
  юридическая обязанность. Отдельный документ: `docs/03_LEGAL_COMPLIANCE.md`.

## 8. Критерии приёмки пилота

1. Собираются данные минимум из 3 открытых источников.
2. Формируется ≥ 50 лидов/мес с объяснением скоринга.
3. Отдел продаж подтверждает полезность ≥ 30% лидов.
4. PII пациентов отсутствуют. Нет обращений юрслужбы по данным.
5. Отчёт выгружается в CSV/JSON/Markdown и открывается в дашборде.
